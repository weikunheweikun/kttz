# 快艇骰子 · 留骰对决 V5

一个无需框架、无需自建后端的静态浏览器游戏。**仅有两个玩法：挑战 AI、P2P 联机。** 可部署到 GitHub Pages，支持手机与桌面。

## 立刻游玩

- 打开 `index.html`（完整源码版，需同目录其余 JS/CSS 文件），或直接打开 `single-file.html`（所有资源打包在一个 HTML）。
- 选「挑战 AI」：填写昵称，选择简单 / 中等 / 困难，点击「开始挑战」。玩家先手，AI 后手。
- 选「P2P 联机」：创建方生成邀请码，另一方粘贴邀请码生成回复码，再传回创建方确认。连接成功后双方轮流操作。
- **没有本地存档。** 刷新、关闭页面或离开会丢失该设备当前局面；P2P 断开后没有持久化恢复。

## 计分规则

- 标准 13 格：1–6 点、三条、四条、葫芦、小顺、大顺、快艇、机会。
- 每人最多 3 次掷骰，每轮第一掷必须手动点击；5 颗骰子的点数 1–6 **由浏览器 `crypto.getRandomValues` 独立等概率生成**，使用拒绝采样避免取模偏差。
- 原上栏 63 分奖励 +35 分。快艇由标准 50 改为 **60 分**，无额外快艇奖励及 Joker 规则；五条也可以计葫芦 25 分。
- 本轮选定一个计分格后，若还有下一轮，可花费 **3 分 / 颗**保留 0–5 颗骰子到自己下一轮。它们默认锁定但可以解除并重掷。最后一轮结束后不能再付费留骰。
- 可以在尚未填写的类别主动计入 0 分。
- 最终总分 = 上栏 + 额外奖励 + 下栏 − 留骰费用。游戏结束会自动出现**双方统计总结弹窗**，也可以关掉查看完整计分卡。

## AI 难度

AI 由 `ai.js` 实现，不依赖后端和外部 AI 服务。每一步都会考虑当前可用计分格、持有的骰子、上栏奖励的可能性与跨轮留骰的费用。

| 难度 | 前瞻范围 | 偶尔选择次优方案的概率 | 当前决策采样预算 |
|---|---|---:|---:|
| 简单 | 本回合（1 回合） | ~16.7% | 12 次/候选 |
| 中等 | 本回合 + 下一回合（2 回合） | 10% | 16 次/候选 |
| 困难 | 本回合 + 后续两回合（3 回合） | 5% | 20 次/候选 |

**算法说明与边界**：采用类别引导的蒙特卡洛搜索、保留费用估值、可用类别机会成本和有限多回合前瞻；未来骰子用预测抽样，并非遍历全部可能对局状态，所以所谓“最优选择”是**搜索范围与采样预算内的近似最优**，不能保证理论上的全局最优。偶尔次优仅影响 AI 选哪个动作，**不会操纵实际骰子**。AI 的模拟随机数独立于真实掷骰，真实点数始终由 `core.js` 的安全随机数生成。

## GitHub Pages 部署

1. 在 GitHub 创建公开仓库，例如 `yacht-dice`。
2. 将 `index.html`、`styles.css`、`core.js`、`ai.js`、`app.js` 上传到根目录（`README.md` 等可选）。
3. 进入仓库 Settings → Pages，Source 选择 `Deploy from a branch`，分支设置为 `main`、目录 `(root)`。
4. 部署后在 `https://你的用户名.github.io/yacht-dice/` 访问。

项目不需要 `npm install`、数据库、构建工具或账号。

## 关于 P2P 直连

- WebRTC DataChannel；无需自建信令服务器，通过聊天软件人工交换 offer / answer 码。
- 通过公共 Google STUN 服务发现可用连接路径。游戏数据经 WebRTC 加密数据通道直接传输，**未配置 TURN 中继**。
- 运营商 NAT、公司防火墙及严格网络可能导致直连失败；移动端切出页面也可能导致连接中断。跨实际运营商与设备的连接可靠性尚未获得完整端到端验证。
- 创建方是对局状态权威，使用本地 `core.js` 的随机数产生结果并同步给对方。它是好友之间的休闲对战，**不提供防作弊、联机断线持久化恢复或自动匹配**。

## 主要文件

- `index.html` — 页面入口
- `styles.css` — 适配 320px / 390px 手机与桌面的视觉设计
- `core.js` — 计分、状态流转、加密安全掷骰
- `ai.js` — 三档 AI 的模拟前瞻算法
- `app.js` — UI、动画、AI 轮换、P2P 和弹窗
- `single-file.html` — 所有代码内联的便携版
- `test_ai.js` — 三个难度的 13 轮完整对局规则测试
- `test_browser.py`, `test_full_browser.py` — Playwright / Chromium 浏览器回归测试（开发用）

## 已测试项目

- Node.js：简单 / 中等 / 困难各完成完整的 13 轮对战、AI 不越权操作、无本地同屏模式。
- Chromium：320px、390px、1280px 新建游戏、切换难度、AI 自动回合、记分、3 分/颗保留及无 JS 错误。
- Chromium：从第 1 轮跑到第 13 轮，自动弹出总结、检查双方细分统计、关闭弹窗、再开新局。
- P2P 连接入口与编码保留，但真实跨网络端到端连接仍需用户在实际设备上验证。
